# 财报季短期期权策略系统：验证、策略对比与施工计划

> 版本 0.2 · 2026-11-04 · 状态：Phase 0 已完成摸底，见 `docs/PHASE0_FINDINGS.md`

---

## 0. 目标与边界

**目标**：构建一套美股财报季交易系统，以 Polymarket EPS 合约的赔率变化为核心信号、Kalshi KPI 合约为补充，结合基本面与期权链数据，在财报公布前后交易短期期权（1 到 2 周到期）。

**边界**：

- 只做财报事件驱动，不做日常择时。
- 只做美股，初期只做有预测市场合约覆盖的标的（预计几十只大盘股）。
- 先验证信号，再比较策略，最后才施工执行层。任何一个阶段不达标即停止，不往下走。
- 初期资金规模小，策略容量不是优先考虑项。

**三条必须先回答的问题**（整个项目的生死线）：

1. 预测市场的 beat 概率对实际 beat 的预测力是否超过历史基准率？
2. 预测市场的赔率变化对财报日股价方向或波幅是否有预测力？
3. 期权市场是否已经把这些信息定价进去了？如果已经定价，edge 就不存在。

## 1. 验证计划

### 1.1 假设清单

| 编号 | 假设 | 检验方法 | 通过标准 |
|---|---|---|---|
| H1 | 预测市场 P(beat) 的校准度好，并且比"历史 beat 率"更准 | 对已结算合约做 reliability diagram，算 Brier score，和 base rate 模型对比 | Brier skill score > 0，且样本量 ≥ 150 个合约 |
| H2 | P(beat) 的 1 日 / 3 日变化对财报日股价方向有预测力 | Logistic 回归，因变量为财报日收益符号，自变量为 ΔP(beat)、修正动量、skew | 样本外 AUC > 0.56，且方向正确率显著高于 50% |
| H3 | 预测市场的不确定性（P 接近 50%、分歧大）与实际波幅 / 隐含波幅之比正相关 | 回归 realized/implied ratio 对 预测市场熵 | 相关系数显著，符号与假设一致 |
| H4 | 预测市场先于期权市场反应，存在 6 到 48 小时的时间差 | 领先滞后相关：ΔP(beat) 与 Δ(25-delta 风险逆转)、ΔIV | 预测市场领先期权在至少一个窗口上显著 |
| H5 | 期权 implied move 相对历史 realized move 的贵贱比本身具有预测力 | 按贵贱比分桶，看各桶的 straddle 收益 | 便宜桶做多 straddle 的平均收益 > 0 且与贵桶有单调关系 |
| H6 | 大单资金流（预测市场的 trade flow imbalance）比价格本身更有信息 | 对比用 trade flow 和用 mid price 两组特征的模型 | trade flow 模型样本外指标更好 |

H1 和 H2 是硬门槛。两者都不通过，项目转为"纯期权波动率策略"，预测市场只做辅助过滤。

### 1.2 数据要求

**预测市场**

- Polymarket（主信号）：每季约 300 家公司有"EPS 是否高于一致预期"二元合约，GAAP 与 non-GAAP 两种口径。Gamma API 负责市场发现，CLOB API 提供价格历史，Data API 提供逐笔成交。单合约成交额中位数已降到几千美元，流动性过滤是必需的。
- Kalshi（补充特征）：没有 EPS 合约，只有 KPI 区间合约（同店销售、客户数、订阅数等）和电话会提词合约。KPI 合约用于零售、餐饮和 SaaS 标的。公开行情接口 `api.elections.kalshi.com/trade-api/v2` 无需鉴权，限流严格。
- 两家都要存**原始订单簿快照**和**成交流**，不能只存最新价。采集频率：平时 15 分钟一次，财报前 48 小时内 1 分钟一次，财报电话会期间 WebSocket 全量订阅。

**基本面与财报日历**

- 财报日期和盘前 / 盘后时点。
- Point-in-time 一致预期 EPS 和营收，以及 30 / 60 / 90 天的修正历史。回测时严禁用最终版预期。
- 历史 beat 率、历史财报日实际涨跌幅（至少 12 个季度）。
- 指引历史、空头比例、机构持仓变化。
- 候选来源：Quartr（本会话已接入 MCP，有财报文字记录和标准化财务数据）、Daloopa（MCP 当前连接失败，待修复）、Polygon、FMP、Finnhub。

**期权链**

- 每日至少三次快照（开盘后、午间、收盘前），财报前一天和当天加密到每小时。
- 每个合约的 bid / ask / last / IV / Greeks / OI / volume。
- 候选来源：Polygon（有历史期权数据）、Tradier（免费沙盒）、ORATS（有历史 IV 与财报波动统计）、ThetaData、IBKR API。

**行情**

- 日线：Yahoo Finance（yfinance），用于 H2 和 H3 的财报日收益。
- 分钟级 K 线：用于回测成交价，数据源在 Phase 3 前确定。

### 1.3 历史数据的现实约束

Polymarket EPS 合约从 2025 年 9 月开始，到 2026 年 11 月已有 5 个财报季、约 1,500 个已结算合约。样本比预期大，但成交量逐季萎缩，早期和近期的信号质量可能不同。这意味着：

- 统计检验的功效有限，不要过拟合。
- 验证阶段以"信号是否有方向性预测力"为主，不以"策略年化收益"为主。
- 必须在数据收集的同时推进研究，不能等"数据够了"。

### 1.4 验证阶段产出

- `research/01_coverage.ipynb`：合约覆盖面与流动性统计。
- `research/02_calibration.ipynb`：H1 校准度检验。
- `research/03_direction.ipynb`：H2 / H6 方向预测力检验。
- `research/04_vol.ipynb`：H3 / H5 波动率检验。
- `research/05_leadlag.ipynb`：H4 领先滞后检验。
- `docs/VALIDATION_REPORT.md`：每条假设的结论和数据。

## 2. 策略对比计划

### 2.1 候选策略

所有策略统一在财报前 1 个交易日收盘前建仓，财报后第 1 个交易日开盘后 30 分钟内平仓，不持有到到期。

| 编号 | 策略 | 信号来源 | 结构 | 用途 |
|---|---|---|---|---|
| S0 | 基准：无脑做多 straddle | 无 | ATM straddle，最近到期 | 验证 IV crush 的基准损耗，所有策略必须跑赢它 |
| S1 | 基准：无脑做空 straddle | 无 | 卖 ATM straddle 或 iron condor | 验证"财报期权普遍偏贵"的常识是否成立 |
| S2 | 波动率贵贱策略 | 仅期权：implied / realized 比 | 便宜做多 straddle，贵做 iron condor | 不依赖预测市场的对照组 |
| S3 | 预测市场方向策略 | ΔP(beat) + 预期修正 + skew 三者一致 | 方向 debit vertical spread | 核心策略 A |
| S4 | 预测市场波动策略 | 预测市场熵 + implied/realized 比 | 高熵且便宜做多 strangle；低熵且贵卖 condor | 核心策略 B |
| S5 | 组合策略 | S3 与 S4 的信号融合 | 方向性 + 波动性混合，如 risk reversal 或 ratio spread | 最终候选 |
| S6 | 期限结构策略 | 前月 IV 远高于次月 | Calendar spread | 低相关补充策略 |

### 2.2 对比指标

每个策略在同一回测框架下输出：

- 每笔交易的收益率、胜率、盈亏比。
- Sharpe、Sortino、最大回撤、Calmar。
- 按财报季分组的稳定性（不能只靠某一季）。
- 按市值和行业分组的稳定性。
- 相对 S0 和 S1 的超额收益。
- 交易成本敏感性：买卖价差取 25% / 50% / 100% 三档。
- 信号延迟敏感性：建仓时间提前或推迟 2 小时的结果变化。

### 2.3 对比规则

- 所有策略用同一份数据、同一套成本假设、同一个时间窗口。
- 参数在前 60% 的时间段上调，后 40% 只做一次样本外评估。
- 一个策略只有在样本外跑赢 S0、S1 和 S2 三个基准时，才算"预测市场带来了增量"。
- 最终选择 1 到 2 个策略进入模拟盘，不选多。

### 2.4 策略对比产出

- `research/10_backtest_compare.ipynb`：所有策略的对比表和分季表现。
- `docs/STRATEGY_REPORT.md`：结论、入选策略、参数和已知弱点。

## 3. 施工计划

### 3.1 技术栈

- 语言：Python 3.12。
- 存储：DuckDB + Parquet 做研究层；进入实盘后迁移到 PostgreSQL + TimescaleDB。
- 调度：初期用 cron 或 APScheduler，稳定后换 Prefect。
- 回测：自研轻量框架，不用通用回测库，因为期权事件驱动回测的特殊性太强。
- 看板：Streamlit。
- 告警：Telegram Bot。
- 执行：IBKR API 优先（期权数据和执行一体），Tradier 作为备选。
- 配置和密钥：`.env` + pydantic-settings，密钥不进仓库。

### 3.3 阶段与里程碑

**Phase 0：可行性摸底（1 周）· 已完成大部分，结论见 `docs/PHASE0_FINDINGS.md`**

- 已完成：覆盖面与流动性统计、历史数据深度核实、H1 初步检验（Brier skill score +0.25，初步通过）。
- 未完成：期权历史数据来源与成本核实，Data API 逐笔成交的可得性。

- 核实 Kalshi 与 Polymarket 的 API 现状：base URL、鉴权、历史数据接口、速率限制。此会话的网络策略当前没有放开这些域名，需要先放开或在本地跑。
- 拉取当前财报季所有财报类合约，统计：有合约的公司数、每个合约的日均成交量、盘口深度、价差。
- 核实历史数据可得性：Kalshi 历史合约接口、Polymarket 价格历史接口能回溯多久。
- 核实期权历史数据来源与成本。
- 产出：`docs/PHASE0_FINDINGS.md`，内容包括覆盖面、流动性、历史数据深度、数据成本估算。
- 决策门：有流动性的合约每季少于 20 家公司，或历史数据回溯不足 2 个财报季，项目改为"先收一季数据再说"。

**Phase 1：数据采集层（2 到 3 周）**

- 实现四个采集器：预测市场（Kalshi、Polymarket）、期权链、基本面、行情。
- 定义统一 schema，所有快照带采集时间戳，所有预期数据带"截至时间"字段。
- 搭好定时任务，开始持续采集，这是不可逆的时间投入，越早开始越好。
- 回填能拿到的历史数据。
- 单元测试覆盖解析逻辑和 schema。
- 产出：持续运行的采集服务，数据质量日报。

**Phase 2：特征与验证（3 到 4 周，与 Phase 1 后半段并行）**

- 实现 features 模块：预测市场特征、期权特征、基本面特征。
- 跑第 1 节的 H1 到 H6。
- 产出：`docs/VALIDATION_REPORT.md`。
- 决策门：H1 和 H2 至少通过一个，否则回到第 0 节的三个问题重新定义项目。

**Phase 3：回测与策略对比（3 周）**

- 实现回测引擎：事件驱动、按 bid/ask 成交、显式建模 IV crush、point-in-time 数据。
- 跑第 2 节的 S0 到 S6。
- 产出：`docs/STRATEGY_REPORT.md`，入选 1 到 2 个策略。
- 决策门：入选策略样本外跑赢三个基准，否则回到 Phase 2 调整特征。

**Phase 4：模拟盘（一个完整财报季，约 6 到 8 周）**

- 实现 signals、execution（paper 模式）、monitor。
- 每个财报日自动生成信号、模拟下单、记录成交与盈亏。
- 看板展示：当天信号、持仓、累计表现、信号与回测的偏差。
- 产出：模拟盘报告，重点是实盘信号与回测信号的一致性，以及实际价差与假设价差的差距。
- 决策门：模拟盘表现与回测的差距在可解释范围内。

**Phase 5：小资金实盘（持续）**

- 接入真实账户，单笔仓位上限为总资金 1% 到 2%，同一日财报敞口上限 5%。
- 保留人工确认环节，至少跑一季后再考虑全自动。
- 每个财报季结束做一次复盘，更新参数和报告。

### 3.4 风控规则（从 Phase 4 起强制执行）

- 单笔仓位：总资金的 1% 到 2%，用 1/4 Kelly 调整。
- 同日财报总敞口：不超过总资金 5%。
- 单一行业敞口：不超过总资金 8%。
- 预测市场流动性过滤：合约过去 3 日日均成交量低于阈值（Phase 0 确定）不出信号。
- 期权流动性过滤：bid/ask 价差超过中间价 10% 不交易。
- 强制平仓：财报后第 1 个交易日开盘后 30 分钟内，不留例外。
- 熔断：连续 5 笔亏损或单季回撤超过 10% 自动停止出信号，人工复盘后重启。

## 4. 已知风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 预测市场流动性极薄，赔率被小额资金推动 | 信号充满噪音 | 成交量过滤、用 trade flow 而不是 mid price、多日平滑 |
| beat 与股价方向不等价 | 方向信号失效 | H2 验证；把指引、whisper、修正动量作为必要的辅助条件 |
| 历史样本少 | 过拟合 | 优先验证信号而非策略；参数尽量少；严格样本外 |
| 期权已经定价预测市场信息 | edge 不存在 | H4 领先滞后检验，不通过就不做方向策略 |
| IV crush 吃掉方向性收益 | 裸买期权亏损 | 默认用 debit spread；只有 implied move 便宜时裸买 |
| Point-in-time 预期数据难获取 | 回测前视偏差 | 从 Phase 1 开始自己存每日快照；历史部分用带时间戳的修正数据 |
| Polymarket 对美国用户的合规限制 | 无法交易或无法获取数据 | 只用其公开数据做信号，不在其上交易；确认 Polymarket US 的可用性 |
| 预测市场在电话会议期间剧烈波动 | 建仓时机错误 | 固定在财报前 1 日收盘前建仓，不在电话会中追单 |
| 数据源成本 | 预算 | Phase 0 估算；优先免费和已接入的来源（Quartr、Tradier 沙盒） |

## 5. 决策门汇总

| 门 | 时点 | 通过条件 | 不通过的处理 |
|---|---|---|---|
| G0 | Phase 0 结束 | ≥ 20 家公司有流动性合约，历史数据 ≥ 2 季 | 先只做采集，等一季 |
| G1 | Phase 2 结束 | H1 或 H2 通过 | 转为纯期权波动率策略，预测市场降级为过滤器 |
| G2 | Phase 3 结束 | 入选策略样本外跑赢 S0 / S1 / S2 | 回到特征工程 |
| G3 | Phase 4 结束 | 模拟盘与回测偏差可解释 | 延长模拟盘一季 |
